## Additional data details {#sec-appendix-data}

### Cleaning

The raw resource, as downloaded from the portal, records `Count` as text rather than as a number, because cells with small counts contain the string `"Suppressed"` in place of a value. Cleaning proceeds in three steps: identifying which cells were suppressed, converting the remaining counts to numbers, and confirming that the two operations agree with each other.

```r
raw_data <- read_csv(here::here("data/01-raw_data/raw_data.csv"), show_col_types = FALSE)

analysis_data <-
  raw_data |>
  mutate(
    is_suppressed = Count == "Suppressed",
    Count = if_else(is_suppressed, NA_character_, Count),
    Count = as.numeric(Count)
  )

write_csv(analysis_data, here::here("data/02-analysis_data/analysis_data.csv"))
```

`is_suppressed` is recorded before `Count` is touched, so it reflects what the portal actually published rather than being inferred afterward from a missing value — this matters because a `Count` could in principle be missing for some other reason, and collapsing both cases into a bare `NA` would make it impossible to tell a suppressed cell from a genuine data problem later on. The `Final_Age (group)` column is left with its original, awkward name at this stage; it is renamed to `age_group` where the analysis data are loaded, rather than in the cleaning script itself, so that the cleaned CSV matches the resource's original column layout.

### Testing

We test the data twice: once on the simulated dataset, before the real data are acquired, and once on the cleaned data, after they are.

The simulated data are tested in Python, using `polars` and `numpy`, against the same distributional parameters used to generate them. Following @tellingstories, writing these tests before acquiring the real data forces the structure of the dataset — its columns, its categories, and the range each one can take — to be specified in advance rather than discovered after the fact. Three checks are applied: that the simulated data frame has the expected columns and that every column takes only values from its expected set; that the observed proportion of each category falls within a tolerance of its simulated probability, using the binomial standard error at each proportion rather than a single fixed tolerance across categories of very different sizes; and that the total count, and the count for each year, match the number of deaths the simulation was told to generate.

The cleaned, real data are tested in R, and check a different thing: not whether the data matches a target distribution, since there is no target for real data, but whether the cleaning step did what it was supposed to.

```r
stopifnot(
  # every cause, age group, and gender value is one of the expected categories
  all(analysis_data$Subgroup %in% c(
    "Acute Drug Toxicity", "Cardiovascular Disease", "Homicide",
    "Other Diseases", "Pending", "Suicide", "Unintentional Injury", "Unknown"
  )),
  all(analysis_data$`Final_Age (group)` %in% c("<20", "20-39", "40-59", "60+", "Unknown")),
  all(analysis_data$Gender %in% c("Female", "Male", "Unknown")),

  # every row of death is in 2022, 2023, or 2024
  all(analysis_data$`Year of death` %in% 2022:2024),

  # Count is missing exactly where, and only where, is_suppressed is TRUE
  all(is.na(analysis_data$Count) == analysis_data$is_suppressed),

  # every recorded count is a non-negative whole number
  all(analysis_data$Count[!analysis_data$is_suppressed] >= 0),
  all(analysis_data$Count[!analysis_data$is_suppressed] ==
        floor(analysis_data$Count[!analysis_data$is_suppressed]))
)
```

The fourth check is the one specific to this cleaning step: it confirms that `is_suppressed` and the missingness of `Count` were derived from the same rows, so a later analysis that filters on one is guaranteed to agree with a filter on the other.

### Testing

We test the data twice: once on the simulated dataset, before the real data are acquired, and once on the cleaned data, after they are.

The simulated data are tested in Python, using `polars` and `numpy`, against the same distributional parameters used to generate them. Following @tellingstories, writing these tests before acquiring the real data forces the structure of the dataset — its columns, its categories, and the range each one can take — to be specified in advance rather than discovered after the fact. Three checks are applied: that the simulated data frame has the expected columns and that every column takes only values from its expected set; that the observed proportion of each category falls within a tolerance of its simulated probability, using the binomial standard error at each proportion rather than a single fixed tolerance across categories of very different sizes; and that the total count, and the count for each year, match the number of deaths the simulation was told to generate.

The cleaned, real data are checked for a different thing: not whether they match a target distribution, since there is no target for real data, but whether the cleaning step did what it was supposed to.
